# Release v0.1.12 - Lightning Fast

**Released:** 2026-02-09  
**Type:** Minor release (non-breaking)

## Highlights

Session listing is now significantly faster thanks to direct database access. KSM now reads kiro-cli's database directly instead of parsing CLI output, eliminating external dependencies and improving reliability.

## What's New

### Blazing Fast Performance
Session listing now queries kiro-cli's SQLite database directly instead of spawning a process and parsing text output.

**Before:** Spawned kiro-cli process, parsed ANSI-colored text output with regex  
**After:** Direct SQLite queries with embedded database library  
**Impact:** Noticeably faster, especially with many sessions. No more process overhead.

### No External Dependencies
Removed requirement for external `sqlite3` CLI tool. KSM now bundles SQLite via the rusqlite library.

**Before:** Required `sqlite3` command-line tool installed  
**After:** SQLite embedded in KSM binary  
**Impact:** Easier installation, fewer dependencies, works out of the box

### Better Formatting
Minor improvements to output formatting for better readability:

- Proper grammar: "1 hour ago" (not "1 hours ago")
- Proper pluralization: "1 msg" (not "1 msgs")
- Cleaner preview truncation at 100 characters

### Automatic Fallback
If database access fails for any reason, KSM automatically falls back to CLI parsing with a warning.

**Impact:** More reliable, graceful degradation, no breaking changes for users

## Technical Changes

- Switched from CLI output parsing to direct SQLite queries
- Added `rusqlite` dependency with bundled SQLite (no external deps)
- Migrated all database operations (list, resume, parent detection) to rusqlite
- Implemented hybrid fallback system for compatibility
- Added hidden `--compare-methods` flag for debugging
