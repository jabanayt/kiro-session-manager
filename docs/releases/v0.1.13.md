# Release v0.1.13 - Open for Business

**Released:** 2026-02-27
**Type:** Patch release (non-breaking)

## Highlights

KSM is now ready for its first public pre-alpha. This release adds dual licensing, comprehensive documentation, GitHub CI/CD, and fixes a critical bug where auto-clean could silently wipe all session metadata.

## What's New

### Pre-Alpha Release Preparation

KSM is now properly licensed and documented for public use.

- Dual licensed under Apache-2.0 OR GPL-3.0-only
- Full documentation suite in `docs/` (installation, configuration, usage, contributing)
- GitHub Actions workflow for automated binary builds on tag push
- GitHub Issue templates for bug reports and feature requests
- Security policy with vulnerability reporting guidelines

**Impact:** Users can now install, configure, and contribute with proper guidance.

### Metadata Protection on Database Failure

Previously, if the kiro-cli database was corrupted, locked, or temporarily unavailable, auto-clean would see zero sessions and interpret all metadata as stale -- deleting everything silently.

**Before:** Database failure during `ksm list` or `ksm resume` could wipe all metadata.
**After:** Auto-clean is skipped when zero sessions are returned, preserving metadata safely.
**Impact:** No more silent metadata loss from transient database issues.

### Auto-Clean Config Option

A new `auto_clean` setting in `~/.ksm/config.toml` lets you disable automatic metadata cleanup entirely.

```toml
# Set to false to disable automatic metadata cleanup
auto_clean = true  # Default: true
```

When disabled, use `ksm clean-metadata` to manually remove stale entries.

**Impact:** Users experiencing recurring database issues can protect their metadata while still using all other features.

## Technical Changes

- Added empty-session guard in `cleanup_stale_metadata()` as defence in depth
- Added `auto_clean` config field with auto-migration for existing configs
- Both `list` and `resume` commands now check config before running cleanup
- README shortened to essentials with links to detailed docs
- Release notes moved to `docs/releases/` and cleaned for public use
