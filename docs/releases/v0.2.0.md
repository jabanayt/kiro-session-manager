# Release v0.2.0 - Architecture Restructure

**Released:** 2026-02-28
**Type:** Minor release (non-breaking)

## Highlights

This release lays the foundation for TUI support, database-backed metadata, and session archival. While no user-facing features changed, the internal architecture has been rebuilt to enable these features in upcoming releases. All existing commands work identically.

## What's New

### Layered Architecture

The codebase has been reorganised into a clean layered structure separating data access, business logic, and presentation.

**Before:** Flat structure with command files handling data access, business logic, and output formatting together.
**After:** Clear layers with models (data types), data (trait-based access), services (business logic), and CLI (thin presentation wrappers).
**Impact:** No user-facing changes. This enables TUI support, database migration, and easier feature development going forward.

### Trait-Based Data Access

All data access now goes through abstract traits (SessionSource, MetadataStore). Concrete implementations can be swapped without changing business logic.

**Before:** Direct function calls to storage and database modules with no abstraction.
**After:** Trait-based interfaces that allow swapping implementations (JSON to SQLite, mock for testing) without touching business logic.
**Impact:** The upcoming metadata database migration (replacing JSON with SQLite) becomes a simple implementation swap rather than a codebase-wide rewrite.

### Structured Error Handling

Added structured error types using thiserror for the library crate, with anyhow in the binary for convenience.

**Before:** All errors handled with anyhow, no structured error types.
**After:** Typed error variants (SessionNotFound, ChainConflict, etc.) in the library, with anyhow convenience in the CLI binary.
**Impact:** Better error messages and future TUI error handling in contextual panels rather than generic stderr output.

### Library Crate

Added lib.rs as a library root. All logic lives in the library crate, with main.rs as a thin entry point.

**Before:** All code in the binary crate, not reusable or independently testable.
**After:** Library crate with public API, thin binary entry point.
**Impact:** Enables future TUI and library API consumers to share the same code without duplication.

## Technical Changes

- Layered architecture: models/ to data/ (traits) to services/ to cli/
- Trait-based data access: SessionSource, MetadataStore abstractions
- Services layer: complete operations returning result structs, never printing
- Two-tier error handling: thiserror (library) + anyhow (binary)
- CLI commands refactored to thin wrappers around services
- New dependencies: thiserror, log, env_logger
- Removed: storage.rs, database.rs, kiro.rs, commands/ directory (replaced by new structure)
- Added: data/, services/, cli/, models/ directories, error.rs, lib.rs
