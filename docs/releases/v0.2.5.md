# Release v0.2.5 - Cache & Speed

**Released:** 2026-03-12
**Type:** Patch release (non-breaking)

---

## Highlights

Session listing is now dramatically faster. A new caching layer eliminates repeated JSON parsing, and an optimised database query reduces cold start time from 1.5 seconds to 50 milliseconds.

---

## What's New

- **Session caching** - Session metadata is now cached locally, making list and chain detection operations near-instant on subsequent runs.

---

## Bug Fixes

- Chain detection no longer slows down with large session lists
- `auto_update` setting preserved during config migration
- `--show-parents` no longer shows redundant chain indicator on main session row

---

## Technical Changes

- Session cache table stores preview, message count, compact tag, and message IDs
- `list_session_updates()` uses index-only scan (avoids reading JSON blobs)
- `get_conversation_with_created_at()` fetches JSON and timestamp in single query
- Typed error variants replace generic `InvalidInput` (NotIndexed, CannotReindexArchived, SessionCompacted, ExchangeNotFound, EmptyArchive)
- V4 schema migration for config format consistency
- Sparse config format for new users

## Known Issues

- When using `ksm index`, you're prompted for a name and tags. These are stored for search results and become the archive name if the session is later deleted. However, `ksm list` shows the session's metadata name, not the index name. A future release will streamline this.
