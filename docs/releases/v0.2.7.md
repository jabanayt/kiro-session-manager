# Release v0.2.7 - Tag Validation and Display Improvements

**Released:** 2026-04-02
**Type:** Patch release (non-breaking)

---

## Highlights

This release fixes two user-reported bugs around tag handling and delete syntax, adds input validation to prevent malformed tags from entering the system, and improves the session list display to make better use of available terminal width.

---

## What's New

- **Tag validation** - Tags now enforce a strict character set (lowercase letters, numbers, hyphens, underscores, and dots). Invalid tags are rejected at creation with a clear error message. Existing malformed tags are flagged on `ksm list` with removal instructions.
- **Wider session list** - The session list now uses the full terminal width, showing more of each session title. Tags that do not fit on one line wrap cleanly to the next line.
- **Notice box** - Warnings and status messages on `ksm list` are now displayed in a styled box with colour-coded borders, making them easier to distinguish from the session list.

---

## Bug Fixes

- Delete command now accepts comma-separated indices (e.g. `ksm d 1,2,3`), matching the syntax shown in the help text
- `ksm tag` with no tag arguments now errors with a clear message instead of silently creating blank metadata
- `ksm untag` with a non-existent tag now errors instead of silently succeeding
- Resume by tag (`ksm r -t tagname`) is now case-insensitive
- Archiving and indexing are blocked if the session has invalid tags, with instructions on how to fix them shown before any prompts
- Delete usage hint removed from `ksm list` output (redundant with `--help`)

## Security

- Tag validation prevents ANSI escape sequence injection via tag names

## Technical Changes

- Schema v5 migration cleans up blank and whitespace tags from both the metadata and archives tables on upgrade
- `migrate_v3_to_v4` now uses a transaction for consistency with other migrations
- `terminal_size()` added to `pager.rs`, replacing the private `terminal_height()` function
- `TAG_RULES` constant added to `services/metadata.rs` as single source of truth for the tag format message
- Notice system (`cli/notices.rs`) added as reusable infrastructure for future warnings and status messages
- `styles::hint()` and `styles::bold()` helper functions added

## Upgrading

No action required. The schema v5 migration runs automatically on first launch after upgrade and cleans up any blank or whitespace tags silently.

If you have tags containing commas or other invalid characters, `ksm list` will show a warning identifying which sessions and tags need fixing, along with instructions on how to remove them.

## Known Issues

- When using `ksm index`, you are prompted for a name and tags. These are stored for search results and become the archive name if the session is later deleted. However, `ksm list` shows the session metadata name, not the index name. A future release will streamline this.
