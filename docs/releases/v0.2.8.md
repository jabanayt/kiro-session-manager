# Release v0.2.8 - TUI/ACP Sessions and macOS Support

**Released:** 2026-04-14
**Type:** Patch release (non-breaking)

---

## Highlights

KSM now supports TUI/ACP sessions alongside legacy sessions, and runs on macOS for the first time. Both session types appear in a unified list, and all commands work correctly across v1 and v2 stores, including when the same session exists in both.

---

## What's New

- **TUI/ACP session support.** Sessions stored at `~/.kiro/sessions/cli/` (created via kiro-cli TUI, JetBrains, or Zed integrations) now appear in `ksm list` alongside legacy sessions, sorted by last activity. Each session shows a `v1` or `v2` marker indicating its storage type.
- **Independent v1/v2 management.** When a legacy session is opened in the TUI, kiro-cli creates a v2 copy with the same session ID. KSM now displays both entries separately and all operations (delete, archive, index, resume) target the correct version. Deleting the v1 entry leaves the v2 entry intact, and vice versa.
- **Resume UI matching.** `ksm resume` automatically opens v1 sessions in the legacy UI and v2 sessions in the TUI. A new `--tui` flag is available to force TUI mode for any session.
- **macOS support.** KSM now runs on macOS with pre-built binaries available for both Apple Silicon and Intel.

Thank you to @oabdellatif for the amazing help with ACP session support.

---

## Bug Fixes

- Resume correctly opens v1 sessions in legacy UI and v2 sessions in TUI
- Delete targets the correct session version (v1 or v2) instead of both
- Archive and index capture content from the correct session version
- Indexed marker only shows on the specific version that was indexed

## Technical Changes

- Composite primary key `(session_id, source_type)` on `session_cache` and `archives` tables
- `SessionSource` trait methods now take `source_type` parameter for explicit routing
- `HybridSource::route()` removed, replaced by `source_type` matching in each method
- `FromStr` implementation for `SourceType` with `KsmError::Parse` error handling
- `KiroDatabase::delete_session` now passes `--session-source v1` to kiro-cli
- Session cache uses directory mtime to skip ACP file scanning when unchanged
- ISO timestamp parsing errors now propagate instead of silently returning 0
- ACP session delete uses kiro-cli instead of direct file removal
- `archive_session` and `index_session` take `&Session` instead of individual fields
- `ArchiveStatus` variants carry `source_type` for targeted lookups
- Pending reindex state stores `session_id:source_type` for correct reindex targeting
- Compile-time macOS database path detection via `cfg!(target_os)`

## Upgrading

No action required. Schema migration runs automatically on first launch. First launch after update will be slightly slower while the session cache rebuilds.

## Known Issues

- When using `ksm index`, you are prompted for a name and tags. These are stored for search results and become the archive name if the session is later deleted. However, `ksm list` shows the session metadata name, not the index name. A future release will streamline this.
